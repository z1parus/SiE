# Тактический ИИ-анализ карты — read-only слой интеллекта

> Папка: `TacticalMapThreesearch`. Идея 2 из 3 (INTELLIGENCE).
> Связана с: `PlanningModuleEvolution` этап 8 (зависимости задач, реализован — `dependsOn`,
> `isTaskUnblocked`, `taskBlockers`, `readyTasks`, `wouldCreateDependencyCycle`), AI-декомпозиция
> (`GroqAiService.decomposeGoal`, реализована).

## Описание

Этап 8 ввёл `dependsOn` и рисует рёбра зависимостей; AI-декомпозиция умеет **создавать** план новой
цели; этап 5 даёт темп. Но **никто не анализирует уже построенную карту**: где критический путь,
какой узел — узкое место (блокирует больше всех), где скопился риск, и как это сформулировать
словами. Сегодня критический путь существует как «набор рёбер зависимостей», но **не
вычисляется** и не подсвечивается.

Этот этап добавляет карте **слой read-only анализа**:

- **подсветка критического пути** (самая длинная цепочка зависимостей);
- **кольца-предупреждения** на узких местах (задачи с наибольшим «влиянием» — транзитивно
  блокируют больше всех);
- переключаемая **тепловая карта риска**;
- **AI-«Тактическая сводка»** — короткий брифинг по-русски от Groq;
- **AI-умная группировка** — предложение `group`-зон по смыслу задач.

Карта из «пространства для рисования» становится «пространством для понимания».

**Главный принцип:** анализ **не мутирует** структуру цели (кроме умной группировки — её
пользователь принимает явным «Принять», как декомпозицию). Все наложения — read-only оверлеи,
считаемые из текущего состояния. Чисто-вычислительные наложения (критический путь, узкие места,
риск) **работают офлайн** — Groq нужен только для сводки и группировки.

## Пользовательский сценарий

1. Владелец цели открывает карту → в палитре «Наложения» включает **«Критический путь»** → самая
   длинная цепочка зависимостей вспыхивает акцентным цветом, вдоль неё тянется пунктир; узкое
   место (задача с наибольшим числом транзитивно ждущих её) получает пульсирующее кольцо-предупреждение.
2. Включает **«Карта риска»** → узлы заливаются по рисковому скору (просрочка + блокирует многих +
   без исполнителя + высокий вес); над тепловой картой — мини-легенда (как `_MemberLegendOverlay`).
3. Тапает **«Тактическая сводка (AI)»** → Groq читает структуру цели + зависимости → возвращает
   2–4 предложения: *«Самый длинный путь: A → B → C, ~18 дней. Узкое место: задача X блокирует
   5 других — закройте X первым. Темп +12%/нед, прогноз впритык к дедлайну.»* Показывается в нижнем
   баннере (не модально).
4. Нажимает **«Предложить зоны (AI)»** → AI кластеризует задачи по смыслу названий → рисует 3–5
   рамок-`group` поверх кластеров с названиями; пользователь «Принять» (создаются
   `MapElement(kind: group)`) или «Отклонить». Это **не новые задачи** — это группировка
   существующих.

## Логика и поведение

### Критический путь и узкие места

Новые чистые функции (новый `tactical_analysis.dart` или расширение `planning.dart`):

- `criticalPath(goal)` — самая длинная цепочка по `dependsOn`, взвешенная по «усилию» (`weight`
  как прокси длительности + поправка на `dueDate` где доступно). Возвращает список task-id. Reuse
  `tasksById` для обхода графа.
- `bottleneckScores(goal)` — для каждой задачи число **незавершённых** задач, прямо или
  транзитивно ждущих её (обратная достижимость по `dependsOn`) = «in-degree влияния».

Оверлей рисуется в существующем `ValueListenableBuilder<_repaint>`-слое:

- `_CriticalPathPainter` — поверх `_EdgePainter`, под узлами: акцентная обводка рёбер цепочки +
  стрелки (переиспользовать `_drawArrowHead`).
- Узкое место — кольцо вокруг узла (`_BottleneckRing` в `_TaskNode`), пульсация через
  `AnimationController`, уважающий `SieMotion.enabled`.

### Тепловая карта риска

`riskScore(task)` ∈ [0,1] — взвешенная сумма: `overdue` (`dueDate < now && !completed`),
`blockingMany` (`bottleneckScore > порога`), `unassigned` (`assigneeIds.empty`),
`highWeight` (`weight == 5`). Режим `risk` в палитре наложений → узлы заливаются градиентом
(нейтральный → янтарь → красный) по скору. Легенда — как `_MemberLegendOverlay`.

### AI-«Тактическая сводка»

- Reuse `GroqAiService` (из AI-декомпозиции). Новый метод `tacticalBriefing(payload)` — системный
  промпт: *«Ты — тактик SiE. Дай короткую сводку по карте цели: критический путь, узкое место,
  главный риск, одно действие на сегодня. ≤4 предложений, по-русски, JSON `{briefing}`.»*
- Пейлоад: иерархия (sub-goals + tasks + `dependsOn` + `completed` + `dueDate` + `assigneeIds`) +
  `velocity`/`projectedCompletion` (этап 5).
- Кэш: in-memory в провайдере + структурная инвалидация (на `addTask`/`deleteTask`/`toggleTask`/
  `addDependency`/`removeDependency`/`completeSubGoal` — сброс). Без отдельной таблицы.
- Приватность: как в декомпозиции — уведомить, что структура отправляется во внешний сервис.

### AI-умная группировка

- `suggestGroups(goal)` → Groq: *«Сгруппируй задачи по смыслу в 3–5 кластеров, верни
  JSON `[{title, taskIds}]`»*.
- Превью: рисуем `group`-рамки (как stage-4 группы) поверх позиций задач, полупрозрачные, с
  заголовком. **Не затирает существующие ручные `group`-элементы** (см. открытые вопросы).
- «Принять» → для каждого кластера `addMapElement(kind: group, content: title, ...)` (этап 4);
  опционально `connector` между ключевой задачей и рамкой. «Отклонить» → очистить превью.
  Уважает `canEdit`.

**Отличие от AI-декомпозиции:** декомпозиция генерирует **новые** под-цели/задачи по имени цели;
умная группировка кластеризует **уже существующие** задачи в карта-нативные зоны. Разный вход и
выход — поэтому две отдельные точки входа, а не «ещё одна кнопка декомпозиции».

### Edge cases

- Нет `dependsOn` у задач → критический путь пуст, «узких мест» нет, сводка: «зависимостей нет —
  путь не определён».
- Циклов нет (этап 8 уже запрещает их через `wouldCreateDependencyCycle`).
- Цель без под-целей → AI-сводка по задачам верхнего уровня.
- Groq недоступен (оффлайн/нет ключа) → AI-функции скрыты/показывают «Требуется сеть»;
  **чисто-вычислительные** наложения (критический путь, риск, узкие места) работают офлайн —
  критично для offline-first.
- Инвалидация кэша сводки — на любую структурную мутацию.

## Схема данных

Новых таблиц нет. Критический путь / узкие места / риск — чистые функции над текущим `Goal`.
AI-сводка и группы — вызовы Groq; группы сохраняются как существующие `MapElement(kind: group)`
(этап 4). Кэш сводки — in-memory в провайдере (TTL + структурная инвалидация).

## Открытые вопросы

1. **Длительность для критического пути.** Без `dueDate` длина цепочки измеряется в чём?
   `weight` как прокси (1→1д, 3→3д, 5→5д) или `dueDate − completedAt` где есть?
   **Рекомендация:** `weight`-прокси + `dueDate`-поправка где доступно.
2. **Кэш AI-сводки.** In-memory (теряется при перезапуске) vs поле в `GoalSettings` vs отдельная
   таблица. **Рекомендация:** in-memory + структурная инвалидация — просто и достаточно.
3. **Лимиты/стоимость Groq.** Debounce + «не чаще 1 раза на цель за N минут» (как декомпозиция);
   уведомление о приватности (структура уходит во внешний сервис).
4. **Уровень анализа.** Только задачи (этап 8) или распространить на под-цели (дерево зависимостей
   под-целей)? **Рекомендация:** сначала задачи; под-цели — опционально.
5. **Группы vs существующие `group`-элементы.** AI не должен затирать ручные группы: превью
   предлагает новые, не трогая существующие; пользователь сливает/заменяет вручную. Подтвердить UX.
