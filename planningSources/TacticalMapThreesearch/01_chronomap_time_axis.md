# Хронокарта — ось времени на тактической карте

> Папка: `TacticalMapThreesearch`. Идея 1 из 3 (TIME).
> Связана с: `TacticalMapEvolution` (8 этапов реализованы), `PlanningModuleEvolution` этап 5
> («Импульс и аналитика темпа», реализован — `goal_progress_snapshots`).

## Описание

Сегодня тактическая карта (`tactical_map_view.dart`) — **плоский пространственный снимок**:
узлы и связи «здесь и сейчас». У цели есть богатая **временная** структура (`created_at` у
под-целей/задач/вех/привычек-связей, `completed_at` у задач, `target_date` и логи у вех,
`deadline` у цели, ежедневные снимки прогресса из этапа 5), но на карте она никак не
представлена — время живёт только на отдельном экране статистики «Импульс».

Хронокарта добавляет карте **ось времени**: пользователь может «перемотать» карту назад и
посмотреть, как цель росла и заполнялась, либо включить **тепловое наложение дедлайнов** и
увидеть, какие узлы горят, успевают/не успевают, и когда при текущем темпе будет финиш. Карта
превращается из 2D-пространства в **пространственно-временную** инструмент.

**Главный принцип:** временной слой — **read-only наложение** поверх существующего рендера. Он не
мутирует цель, не требует `canEdit` (доступно viewer-ам), считается из уже существующих полей и
**в v1 не вводит новых таблиц**.

## Пользовательский сценарий

1. Пользователь открывает тактическую карту зрелой цели → внизу появляется компактная
   **временная шкала** (`createdAt` → `сегодня` → `deadline`).
2. Тянет ползунок в прошлое → узлы, которых ещё не существовало, исчезают (или рисуются
   «призраком»); задачи, не завершённые на эту дату, подсвечиваются как открытые; вехи «гаснут».
   Видно, как карта заполнялась неделями.
3. Отпускает ползунок на «сегодня» → карта возвращается к актуальному состоянию.
4. Включает режим **«Дедлайны»** в палитре наложений → узлы окрашиваются по срочности
   (`>7 дней` зелёный → `3–7 дней` янтарный → `<3 дней / просрочка` красный с пульсацией); на шкале
   появляется **прогноз-финиш** — пунктирная отметка даты завершения при текущем темпе (из
   `goal_progress_snapshots` этапа 5). Если прогноз правее `deadline` — отметка красная.
5. Тап по узлу в режиме дедлайнов → мини-карточка: «До дедлайна задачи: 3 дня. Ждёт 2 задачи.»
6. Тап по точке-событию на шкале → перемотка к этой дате + `_centerOnLogical` ближайшего узла.

## Логика и поведение

### Режим перемотки (Replay)

Источник событий — **существующие временные метки, без новой таблицы**:

| Событие | Поле-источник |
|---|---|
| Появление узла | `SubGoal.createdAt`, `PlanningTask.createdAt`, `Milestone.createdAt`, `GoalHabitLink.createdAt` |
| Появление карта-элемента | `MapElement.createdAt` |
| Завершение задачи | `PlanningTask.completedAt` |
| Завершение вехи | последняя `MilestoneLog.recorded_at` (или `isCompleted`) |

- **Позиции в прошлом не восстанавливаются.** Сохранённых исторических позиций нет
  (`mapPositions` перезаписывается при каждом drag). Поэтому на любом прошлом срезе узлы
  рисуются по **текущим сохранённым позициям**. Перемотка показывает «что существовало и что было
  сделано», а не «где это лежало тогда». Это явное ограничение v1 (см. открытые вопросы).
- Точка отсчёта шкалы — `goal.createdAt`; правый конец — `max(deadline, now)` (или `now + 30д`
  при отсутствии `deadline`). Ползунок snap-ится к дням.
- Узлы, отсутствующие на выбранном срезе, рисуются «призраком» (`Opacity 0.12`) либо скрываются
  (переключатель в палитре наложений). Рёбра к/от отсутствующих узлов скрываются.
- Задачи, завершённые «в будущем относительно среза», показываются как открытые
  (инвертируется `isCompleted` по правилу `completedAt > slice`).

### Тепловое наложение дедлайнов (Deadline overlay)

- Режим-переключатель в новой **палитре «Наложения»** (рядом с палитрой инструментов `_MapToolPalette`,
  но работает в просмотре, не требует `canEdit`).
- Цвет узла-задачи считается из `dueDate`:
  - нет `dueDate` → нейтральный;
  - `> 7 дней` → спокойный зелёный оттенок;
  - `3–7 дней` → янтарный;
  - `< 3 дней` / просрочка → красный; у просроченных — пульсация через отдельный
    `AnimationController` (уважает `SieMotion.enabled`, как `_hoverAnim`).
- SubGoal/вехи: sub-goal наследует ближайший `dueDate` своих задач; веха — по `targetDate`.
- «Сейчас»-линия на шкале; «прогноз»-отметка из `goal_progress_snapshots` (этап 5):
  `projectedCompletion(goal, velocity)` — пунктир, цвет по соотношению `now / deadline / projected`.

### Временная шкала (нижний оверлей)

- Компактная полоса под холстом, **вне трансформации** (как `_MiniMap`): ось времени, метки
  `createdAt / now / deadline / projected`, точки-события (завершения вех/под-целей — крупные
  маркеры; завершения задач — мелкие, видны при зуме шкалы). Сворачиваемая.
- Слушает `_repaint` (как мини-карта), чтобы cheap-обновляться при pan/zoom без корневого `build`.

### Edge cases

- Цель без под-целей/задач → шкала есть, но пуста; наложение дедлайнов скрыто.
- Нет `deadline` → правый конец = `now` (или `+30д`); burndown/прогноз-отметка по дедлайну скрыта,
  velocity-прогноз остаётся.
- Velocity ≤ 0 / `< 3` снимков → «прогноз» не рисуется («Собираем данные о темпе…»), как в этапе 5.
- `!canEdit` (viewer) → может перематывать и смотреть наложения, но не редактировать (наложения
  read-only).
- Live-холст (этап 8) во время перемотки → чужие курсоры рисуются, но remote-перемещения не
  применяются к прошлому срезу (только к «сегодня»).
- `recurrenceRule` задачи → для перемотки считаем «выполнена на срез» по `completedAt` последнего
  сгенерированного экземпляра; семантику уточнить (открытый вопрос).
- Fog of War при перемотке → временно гасится (показываем всё, что существовало на срезе), см.
  открытые вопросы.

## Схема данных (v1 — без новой таблицы)

Все события перемотки выводятся из уже существующих полей: `created_at`
(sub_goals/planning_tasks/milestones/goal_habit_links/goal_map_elements), `completed_at`
(planning_tasks), `milestone_logs.recorded_at`, `goal_progress_snapshots` (прогноз). Миграций БД
не требуется.

Опциональное расширение (открытый вопрос #1) — append-only `goal_map_events` для полной
пространственной истории (позиции + тонкие события).

## Открытые вопросы

1. **История позиций.** v1 не показывает «где узел лежал тогда» — только «что существовало и было
   сделано». Полная пространственная перемотка требует append-only
   `goal_map_events(action, node_ref, x, y, payload, at)`; это +1 Drift-таблица
   (`schemaVersion 35 → 36`) + Supabase + синк. Вводить сейчас или отложить?
   **Рекомендация:** отложить — ценность «как росла карта» покрывается v1, а история позиций
   дорога и шумна (drag уже дебаунсится 300мс, лог раздувается).
2. **Частота точек на шкале.** Для старых целей с сотнями событий шкала зашумлена. Прореживать по
   значимости (только завершения вех/под-целей + дедлайны)?
   **Рекомендация:** да, крупные маркеры — только «крупные» события; завершения задач — лишь при
   наведении/зуме шкалы.
3. **Recurring-задачи в перемотке.** Считать «выполнена на дату» по последнему `completedAt` —
   упрощение. Уточнить семантику совместно с этапом 3 (повторы).
4. **Взаимодействие с Fog of War.** Перемотка временно гасит Fog или уважает scouted-множество?
   **Рекомендация:** временно гасит (показывает всё, что существовало на срезе) — иначе
   ретроспектива теряет смысл.
5. **Где живёт `_TimeMode`.** Локальный state экрана (как `_editMode`) vs `GoalSettings` (персист
   между сессиями)? **Рекомендация:** локальный — это режим просмотра, не настройка цели.
