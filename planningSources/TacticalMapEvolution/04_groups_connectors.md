# Этап 4 — Группы-зоны и свободные связи

## Описание

Два карта-нативных структурных инструмента, помогающих **организовать мышление на холсте** без
влияния на дерево плана:

1. **Группы-зоны** (`kind = group`) — полупрозрачные подписанные прямоугольники-рамки, визуально
   объединяющие узлы в кластеры: «Фаза 1», «Бэкенд», «Q1», «Зона риска». Узлы внутри не меняют свою
   принадлежность в дереве — это чисто визуальная группировка.
2. **Свободные связи** (`kind = connector`) — стрелки, которые пользователь рисует между **любыми**
   двумя объектами (узел↔узел, узел↔заметка, заметка↔изображение), с опц. подписью и стилем. Это
   **не** иерархические рёбра и **не** зависимости задач — это произвольные смысловые связи
   («влияет на», «см. также», «риск»), существующие только на карте.

Оба — частные случаи `MapElement` из этапа 1; новых таблиц не требуется.

## Пользовательский сценарий

### Группы
1. В палитре — инструмент **«▭ Группа»**. Пользователь рисует прямоугольник (drag по холсту) →
   создаётся зона с дефолтным заголовком и цветом.
2. Зону можно перемещать (тащит саму рамку, не узлы), менять размер, цвет, заголовок, удалять.
3. Узлы, попавшие внутрь рамки, визуально «в группе»; при перетаскивании зоны можно опц.
   «перемещать вместе с содержимым» (тумблер в контекст-меню зоны).

### Связи
1. В палитре — инструмент **«↘ Связь»**. Тап по объекту-источнику → тап по объекту-цели → рисуется
   стрелка.
2. Связь можно подписать (метка посередине), выбрать стиль (сплошная/пунктир, цвет), удалить.
3. Стиль и цвет отличают её от иерархических рёбер (`_EdgePainter`) и зависимостей.

## Логика и поведение

### Группы (`kind = group`)
- Поля: `x,y,w,h` (геометрия рамки), `content` (заголовок), `color_hex`.
- Слой — **самый нижний** (под изображениями и узлами), чтобы рамка была «подложкой».
- «Принадлежность» узла группе вычисляется **геометрически** (bounding-box содержит центр узла) —
  не хранится в БД (проще, не ломает дерево). Для «двигать вместе» при `onPanUpdate` зоны
  применяем дельту ко всем узлам, чьи центры внутри рамки на момент `onPanStart`.
- Рендер: `_GroupZoneElement` — `Positioned` рамка с заливкой `color.withValues(alpha: 0.06)`,
  бордером, заголовком в углу.

### Связи (`kind = connector`)
- Поля: `from_ref`, `to_ref` (ID объекта: узла плана или другого `MapElement`), `content` (метка),
  `style_json` (`{dashed, color, arrow}`).
- `from_ref`/`to_ref` хранят **строковый ID** + неявный тип (узел плана vs map-элемент); резолв
  координат на рендере — из `_positions` (узлы) или из самих элементов.
- Рисуется **новым пейнтером** `_ConnectorPainter` в `_repaint`-слое, отдельно от `_EdgePainter`
  (другой стиль, кривизна, наконечник), чтобы не смешивать с иерархией/зависимостями.
- Если один из концов удалён — связь авто-удаляется (проверка при загрузке/рендере).

### Edge cases
- **Связь сама на себя** — запретить (`from_ref == to_ref`).
- **Дубликаты связей** — допустимы (разные смыслы/метки); не блокируем.
- **Перемещение конца связи** — связь следует за объектом (координаты резолвятся динамически).
- **Группа без узлов** — допустима (можно подписать пустую зону заранее).
- **Viewer** — видит, не редактирует.
- **Производительность** — связи и группы в `_repaint`-слое; `_ConnectorPainter` использует те же
  приёмы дешёвого рисования путей, что `_EdgePainter` (Bezier/dash).

## Схема данных

Без новых таблиц. Используется `goal_map_elements`:
```
ГРУППА:    kind='group',     x,y,w,h, content=заголовок, color_hex, z_index=низкий
СВЯЗЬ:      kind='connector', from_ref=<id>, to_ref=<id>, content=метка,
            style_json={"dashed":true,"color":"#C8A84B","arrow":"end"}
```

`from_ref`/`to_ref` формат: `node:<uuid>` для узлов плана, `el:<uuid>` для map-элементов — префикс
снимает неоднозначность резолва координат.

## Открытые вопросы

1. **Геометрическая vs явная принадлежность группе.** Рекомендация: MVP — геометрическая (bbox),
   нулевая нагрузка на схему; явные membership-связи — позже, если понадобится «свернуть группу».
2. **Сворачивание группы** (collapse в один значок). Рекомендация: вне MVP; ценно для больших карт,
   вынести в этап навигации (7) как расширение.
3. **Связь с автотрассировкой** (обход узлов) vs прямая кривая. Рекомендация: прямая Bezier (как
   зависимости) — дёшево; умная трассировка — позже.
4. **Стрелки между картами/целями.** Рекомендация: нет — только в пределах одной цели (как
   зависимости), кросс-цель усложняет RLS и резолв.
