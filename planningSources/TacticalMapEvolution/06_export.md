# Этап 6 — Экспорт: Markdown (.md) и снимок карты (PNG)

## Описание

Возможность **вынести цель наружу**: экспортировать всю структуру цели в читаемый **Markdown-файл**
(`.md`) и/или сохранить **снимок тактической карты в PNG**. Это закрывает запрос на переносимость
(поделиться планом, вставить в Notion/Obsidian/документ, заархивировать, распечатать визуальную
карту).

Этап **read-only по своей сути** (сериализация существующих данных) — низкий риск, не трогает схему
БД, но добавляет 2 пакета (`share_plus`, `path_provider`).

## Пользовательский сценарий

1. В шапке `MissionDetailScreen` (рядом со Stats/Settings) — кнопка **«Экспорт»** → bottom-sheet с
   выбором: **«Markdown (.md)»** / **«Снимок карты (PNG)»**.
2. **Markdown:** генерируется структурированный документ (см. формат ниже) → системный share-sheet
   (`share_plus`) для сохранения/отправки. Опц. предпросмотр перед экспортом.
3. **PNG:** карта рендерится в изображение (через `RepaintBoundary` → `toImage`), сохраняется/шарится.
   Опционально — «вся карта» (с авто-fit по контенту) или «как на экране».

## Логика и поведение

### Markdown-генератор (чистая функция)
- Новый чистый сериализатор `goalToMarkdown(Goal goal, {include})` в `sie_core` — без сайд-эффектов,
  легко тестируется.
- Содержимое:
  - Заголовок (имя цели), статус, прогресс %, дедлайн, категория, «Зачем» (`settings.why`).
  - Дерево: под-цели (рекурсивно) с чек-боксами `- [x]/[ ]`, задачи с весом (`×1/×3/×5`), дедлайнами,
    повторяемостью, **исполнителем** (этап 5, если есть).
  - Вехи: бинарные (`[x]`) и метрические (`current/target unit`, прогресс %).
  - Зависимости задач (этап 8 Planning) — секция «Блокировки».
  - **Заметки/метки карты** (этап 1) — секция «Заметки с карты».
  - Связанные привычки (синергия).
- Формат — валидный GitHub-Flavored Markdown (чек-листы, заголовки, таблицы для метрик).

### PNG-снимок
- Обернуть холст карты в `RepaintBoundary` (`GlobalKey`), `boundary.toImage(pixelRatio)` →
  `ByteData(png)`. Для «всей карты» — временно установить трансформацию fit-to-content перед захватом.
- Учесть текущую тему (`SieBackground` фон).

### Файлы и шаринг
- `path_provider` → временная директория; имя `{goalName}_{date}.md` / `.png`.
- `share_plus` → `Share.shareXFiles([...])`.

### Edge cases
- **Большая карта** для PNG — клампить `pixelRatio`, чтобы не превысить лимит размера текстуры;
  при превышении — экспорт «как на экране» с предупреждением.
- **Fog of War** — экспорт включает всё (владелец/editor); для viewer уважать видимость? Рекомендация:
  экспортирует только тот, кто видит полную структуру (owner/editor).
- **Офлайн** — экспорт работает полностью офлайн (данные локальны; share — системный).
- **Пустая цель** — корректный минимальный `.md` (только заголовок).

## Схема данных

Без новых таблиц. Пример выходного `.md`:
```markdown
# 🎯 Запуск продукта
**Статус:** active · **Прогресс:** 62% · **Дедлайн:** 2026-08-01
**Категория:** project
> Зачем: выйти на стабильный доход и доказать гипотезу

## Операции
- [ ] **Бэкенд** — 3/5 задач (60%)
  - [x] Схема БД ×3  ·  @Алиса
  - [ ] API аутентификации ×5  ·  @Боб  ·  до 2026-06-20
  - [ ] Очередь задач ×3  (🔁 weekly:1,3,5)
- [x] **Лендинг** — завершено

## Контрольные точки
- [ ] Накопить $5000 — **3200 / 5000 USD** (64%)
- [x] Первые 10 пользователей

## Блокировки
- «Запустить рекламу» ждёт: «Готов лендинг», «Настроена аналитика»

## Заметки с карты
- 📌 «Узкое место — найм бэкендера»
- 📌 «Идея: партнёрка с X»
```

## Открытые вопросы

1. **Импорт обратно из `.md`.** Рекомендация: вне scope (экспорт — односторонний); двусторонний
   sync с Obsidian — крупная отдельная фича.
2. **PDF-экспорт.** Рекомендация: позже; `.md` + PNG покрывают 90% потребности.
3. **Экспорт всех целей разом / бэкап.** Рекомендация: отдельная фича уровня профиля, не карты.
4. **Вотермарк/брендинг SiE на PNG.** Рекомендация: лёгкий логотип в углу снимка (узнаваемость при
   шаринге) — опционально.
