# Опора 1: Активность модуля авто-выполняет привычку (activity → habit)

## Описание
Сейчас связь «привычка → цель» уже есть (`goal_habit_links` + `applyHabitBoost`): выполнение привычки бустит цель. Но привычки нельзя выполнить активностью из других модулей — хотя логически «помедитировать 10 минут», «глубокая работа 25 минут», «дыхательная практика» — это и есть привычки, которые пользователь и так закрывает в соответствующих модулях, дублируя отметку вручную.

**Идея:** обобщить паттерн — у привычки появляется необязательный **«источник выполнения»**: завершение активности в модуле (Фокус / Дыхание / Медитация / выполнение задачи Планирования) **автоматически** засчитывает привычку за сегодня. Один механизм разом соединяет **Фокус→Привычки, Дыхание→Привычки, Медитация→Привычки, Планирование→Привычки**.

## Пользовательский сценарий
1. Пользователь создаёт/редактирует привычку → новый раздел «Засчитывается активностью» → выбирает источник (напр. «Сессия медитации») и, для `count`/`duration`-привычек, порог (напр. «≥ 10 мин»).
2. Пользователь просто идёт в модуль Медитации и завершает сессию 12 минут.
3. **Автоматически:** привычка «Медитация» отмечается выполненной за сегодня; срабатывает существующий synergy-boost на связанные цели.
4. В **Оперативной сводке** появляется системное сообщение: «Протокол «Медитация» закрыт автоматически — сессия 12 мин». Есть **Undo**.
5. Если привычка уже была отмечена вручную сегодня — повторно не задваивается.

## Логика и поведение
### Точка перехвата
- Централизованно в `SessionCompletionNotifier` (`achievements_provider.dart`) — он уже единая точка записи сессий Фокуса/Дыхания/Медитации. Для Планирования — в месте завершения задачи (`planning_provider`).
- После записи сессии: найти привычки, у которых `source` соответствует модулю и выполнен порог → авто-залогировать привычку за сегодня через существующий путь лога (`habits_provider.toggleHabit`/`logHabit`), что автоматически запустит synergy-boost целей.

### Порог и типы привычек
- `binary` — любое завершение активности закрывает привычку.
- `count`/`duration` — активность добавляет значение (напр. минуты фокуса) к дневному счётчику; привычка закрывается по достижении цели дня. Несколько сессий за день суммируются.

### Защита от дублей и злоупотреблений
- Идемпотентность: если за сегодня привычка уже выполнена вручную — не логировать повторно (для `binary`); для `count` — не превышать доверенный предел (см. `xp-anti-farming.md`).
- Undo в сводке откатывает авто-лог и связанный boost.

### Витрина в Сводке
- Авто-выполненные сегодня привычки → системное сообщение в блоке Привычек и/или в приветствии Сводки (переиспользуем набор `operationalBrief`).

### Переиспользуется
- `goal_habit_links`/`applyHabitBoost` (каскад на цели), путь лога привычки, набор системных сообщений Сводки.

## Схема данных
- **`activity_habit_links`** (рекомендуется таблица, а не поле — привычку может закрывать несколько источников):
  - `id`, `habit_id`, `source` (`focus`|`breathing`|`meditation`|`task`), `min_value` (nullable — порог: минуты/раунды/кол-во), `created_at`, `synced`.
- Альтернатива для MVP: nullable `fulfillment_source` + `fulfillment_min` прямо на `habits`.
- Drift-миграция + Supabase-таблица + RLS (owner-only, как у остальных пользовательских таблиц).

## Принятые решения (реализация)
1. **Схема:** отдельная таблица `activity_habit_links` (несколько источников на привычку).
2. **Порог count/duration:** суммировать факт — активность добавляет своё значение (минуты для `duration`, +1 для `count`) к дневному счётчику; binary — закрывается любой подходящей активностью.
3. **Планирование:** источник «task» закрывает привычку только при выполнении задачи по **связанной цели** (через существующий `goal_habit_links`).
4. **Цепочка (Этап 1):** дыхание закрывает привычки-источник «breathing», медитация — «meditation» (обе).
5. **Витрина в Сводке + Undo** — отложено на следующий заход (авто-выполнение уже видно в списке привычек).

## Открытые вопросы
1. **Таблица или поле на привычке** для MVP (несколько источников на привычку — нужно ли сразу)?
2. **Семантика порога** для `duration`/`count`: минимальная длительность закрывает целиком, или активность добавляет фактические минуты к счётчику?
3. **Планирование как источник:** «выполнение любой задачи» или «задача, привязанная к конкретной привычке/цели»?
4. **Ретроактивность:** учитывать сессии, записанные до создания привычки/линка? (скорее нет.)
5. **Уведомление:** показывать авто-выполнение только в Сводке или ещё тост сразу после сессии?
6. **Взаимодействие с Этапом 1:** дыхательная практика «в составе медитации» — закрывает привычку дыхания, привычку медитации, обе или ни одной?
