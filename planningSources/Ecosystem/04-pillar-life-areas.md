# Опора 3: «Сферы жизни» как общая ось

## Описание
На привычках уже есть ось **«Сферы жизни»** (`LocalHabits.area`: `health`|`mind`|`productivity`|`relationships`|`finance`|`spirit`). У целей, focus/breathing/meditation-сессий её нет. Если сделать сферу **общей осью** для всех модулей, появятся сквозные срезы («как у меня дела в сфере Здоровье» по всем модулям) и умные подсказки — без попарных связей.

Это самая крупная из трёх опор; идёт последней и может внедряться поэтапно.

## Пользовательский сценарий
1. У цели, как у привычки, появляется тег сферы (напр. «Здоровье»).
2. Сессии (фокус/дыхание/медитация) наследуют сферу от связанной цели/задачи/пресета либо получают дефолт.
3. В Сводке (или профиле) — блок **«Баланс сфер»**: по каждой сфере агрегируется активность из всех модулей (сколько привычек, целей, сессий, времени за неделю).
4. **Умные подсказки:** цель в сфере «Здоровье» предлагает профильные привычки/практики; перекос («в сфере Отношения — ноль активности 2 недели») подсвечивается мягким сообщением.

## Логика и поведение
- Единый источник значений сферы (уже неявно задан значениями `area` привычек) — вынести в общий enum/справочник `LifeArea`.
- **Наследование сферы сессиями:** focus-сессия берёт сферу от `goalId`/`taskId`; медитация — от пресета/цели; дыхание — от контекста (или «spirit»/«health» по умолчанию).
- **Срезы:** провайдер-агрегатор `life_areas_provider`, собирающий по сфере данные из привычек, целей и сессий (переиспользуя существующие провайдеры/`select`).
- **Подсказки:** на основе среза (пустые/перекошенные сферы) — сообщения в Сводке.

## Затрагиваемые модули
### Изменяемые файлы
| Файл | Изменение |
|------|-----------|
| `packages/sie_core/lib/src/local/app_database.dart` | `area` на `local_goals` (+опц. на `meditation_presets`); наследование на сессиях |
| Модель/enum `LifeArea` (новый общий) | Единый справочник сфер (значения = как у привычек) |
| `planning_provider` / экран цели | Выбор сферы у цели |
| Новый `life_areas_provider` | Сквозной агрегатор по сферам |
| `operations_control_screen.dart` (Сводка) | Блок «Баланс сфер» + подсказки о перекосах |
| Focus/Meditation/Breathing session recording | Проставление сферы сессии по контексту |
| i18n: общий namespace `lifeAreas`, `operationalBrief` (ru+en) | Названия сфер + сообщения |

### Переиспользуется
- Значения `area` привычек, связи цель↔задача↔сессия (goalId/taskId), лента Сводки.

## Схема данных
- **`local_goals` / `goals`:** новый nullable `area`.
- (Опц.) **`meditation_presets`:** `area`; сессии — денормализованный `area` (nullable) для быстрых срезов, либо вычисление на лету по линкам.
- Drift-миграция + Supabase-колонки + RLS без изменений.

## Открытые вопросы
1. **Фиксированный набор сфер или пользовательские** (сейчас у привычек фиксированный)? Рекомендация — оставить фиксированный, синхронизировать со списком привычек.
2. **Где витрина «Баланс сфер»** — блок в Сводке, экран в профиле, или и то и другое?
3. **Сфера сессий без цели/пресета** — дефолт по модулю или «без сферы»?
4. **Денормализация `area` на сессии** (для скорости) или всегда вычислять по линкам?
5. **Как подавать перекос** — мягко (одно сообщение) или отдельная аналитика; не превращать в «обязаловку» закрывать все сферы.
6. **Связь с Опорой 2 (Тонус):** нужен ли Тонус/активность в разрезе сфер?
