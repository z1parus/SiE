# WidgetWarriors — Бэклог полировки

Накопитель задач, отложенных на этап финальной полировки. Не блокируют
функциональность, но улучшают восприятие и UX.

## 1. «Живой» посекундный отсчёт таймера Фокуса на виджете ✅ (сделано, v2.7.34)

**Реализовано.** Поверх PNG-виджета Фокуса наложен нативный Android
`Chronometer` с обратным отсчётом (`isCountDown`, API 24+ — minSdk поднят до 24).
Когда сессия запущена, PNG рисует кольцо/фазу/задачу, но оставляет место под
время пустым, а нативный `Chronometer` тикает посекундно сам по себе, без
фоновых обновлений. Под каждый размер (small/medium/large) — свой layout
(`widget_focus_small/medium/large.xml`) с хронометром, позиционированным над
центром кольца через весовые `Space`-распорки (чтобы попадать в место под
fitXY-растяжением PNG). Dart прокидывает `widget_chrono_<id>` = `endMs|argbColor`
и `widget_size_<id>`; native выбирает layout по размеру и пересчитывает базу
отсчёта от `SystemClock.elapsedRealtime()` при каждом обновлении.

---

<details>
<summary>Исходная постановка задачи</summary>

**Проблема.** Сейчас виджет Фокуса — это отрисованный Flutter PNG. Он
обновляется только событийно (старт / пауза / смена фазы / открытие
приложения). Между событиями картинка «заморожена» — цифры таймера на
домашнем экране не уменьшаются в реальном времени.

**Почему нельзя решить фоновым обновлением.** `WorkManager` / периодический
рефрингеш на Android имеет минимальный интервал 15 минут — посекундно тикать
так невозможно. PNG-подход в принципе не умеет тикать сам по себе.

**Решение (на этап полировки).** Перевести отображение времени на нативный
Android `Chronometer` (или `TextClock`-подобный механизм обратного отсчёта),
наложенный поверх PNG-виджета:

- В `widget_focus.xml` добавить `<Chronometer>` поверх `ImageView`, видимый
  только когда сессия запущена (`isRunning == true`).
- Из Dart прокидывать в `HomeWidget`-storage `focus_chrono_base` — момент
  окончания фазы (`SystemClock.elapsedRealtime() + secsRemaining*1000`), фазу,
  и флаг `isRunning`.
- В `FocusWidgetProvider.kt`:
  - `chronometer.base = base`
  - `chronometer.isCountDown = true` (API 24+)
  - `chronometer.format` / показывать `MM:SS`
  - `chronometer.start()` если running, иначе `stop()` + скрыть, показать PNG-время.
- PNG продолжает рисовать кольцо/фазу/задачу; динамические только цифры времени.

**Нюансы.**
- `Chronometer.isCountDown` доступен с API 24 — проверить `minSdk` (сейчас 21).
  Если нужно поддержать <24, считать вручную через периодический tick или
  показывать прошедшее время вместо обратного.
- При паузе — `stop()` и зафиксировать оставшееся время текстом.
- Тема: цвет текста `Chronometer` задавать под акцент фазы (work/break/idle).

</details>

## 2. Искажение элементов при ресайзе виджета (fitXY)

**Проблема.** PNG растягивается под фактические ячейки лаунчера через `fitXY`,
из-за чего текст и кольца сжимаются/растягиваются при нестандартном размере
ячеек.

**Решение (future).** Рендерить под фактический размер ячейки
(`getAppWidgetOptions` → min/max width/height) вместо фиксированных
160/320 логических размеров; либо ограничить ресайз в `*_info.xml`.

## 3. Config-activity при размещении виджета

Сейчас размещённый из лаунчера виджет провижинится дефолтным конфигом, Студия
открывается отдельно через Профиль → «Мои виджеты». На полировку — опциональная
`configure`-activity, открывающая Студию сразу при перетаскивании виджета.

## 4. Периодическое фоновое обновление

`workmanager 0.5.2` несовместим (ошибки сборки, убран). На полировку — подобрать
совместимую версию или нативный `AlarmManager`/`JobScheduler` для редкого
(раз в 15–30 мин) рефреша «спящих» виджетов (день-роллловер привычек и т.п.).
