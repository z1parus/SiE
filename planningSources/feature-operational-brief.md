# План: Оперативная сводка (Operational Brief) — новый режим главного экрана

> **Цель:** Превратить главный экран Operations из неинформативной карусели модулей в персонализированную ленту-сводку в духе Samsung One UI «Now Brief»: система приветствует оперативника и по каждому модулю выдаёт краткое, персональное обращение с призывом к действию, ведущее внутрь модуля.

**Режим:** Планирование → Реализация
**Ключевой принцип:** режим карусели **сохраняется**; Сводка накатывается поверх как второй режим, с переключателем сверху и плавным переходом. Сводка должна покрыть **весь** текущий функционал главного экрана, чтобы в будущем от карусели можно было отказаться безболезненно.

---

## 1. Описание

Сейчас главный экран (`operations_control_screen.dart`) = шапка (SiE OPERATIONS CONTROL + имя + XP-бар) → секция «Отделы» (daily-tip баннер + плитка «Суточный Авангард» → лидерборд + горизонтальная карусель 5 модулей с превью-графикой, статусом и reorder). Карусель гибкая, но не даёт стимула и призыва к действию.

**Оперативная сводка** — вертикальная лента блоков, где каждый блок — «обращение системы к оперативнику» по конкретному модулю: приветствие по времени суток, персональная выжимка (что сделать сегодня / что осталось / последние сессии) и CTA внутрь модуля. Графические превью модулей сохраняются и обыгрываются внутри блоков.

### Модули (5, как в карусели)
`planning` · `habit_archive` · `focus_protocol` · `breathing_practices` · `meditation`

---

## 2. Пользовательский сценарий

1. Оперативник открывает вкладку «Операции». Сверху — переключатель **«Сводка / Модули»** (по умолчанию — см. открытый вопрос №6).
2. В режиме **Сводки** видит приветствие: «Добрый вечер, {ОПЕРАТИВНИК}» (по локальному времени устройства) и ленту блоков.
3. Каждый блок — короткое обращение + персональные данные + превью-графика + кнопка/тап «перейти». Например:
   - «Оперативник, по операции «{Цель}» на сегодня остаётся задача: {задача}. А также ещё {N} задач…» → тап ведёт в Планирование.
   - «Осталось {N} протоколов на сегодня» / «Все протоколы дня выполнены — дисциплина безупречна. День {streak} без срыва по «{avoid-привычка}» — так держать.» → Привычки.
   - «Готовы к сессии глубокого труда? Последняя: {дата}.» → Фокус. Аналогично Дыхание / Медитация.
4. Нажимает переключатель → плавный (fade/slide) переход обратно в привычную **карусель**. Выбор режима запоминается.
5. Весь прежний функционал (лидерборд, советы дня, XP/профиль, nav-bar, pull-to-refresh, offline) остаётся доступен в обоих режимах.

## 3. Логика и поведение

### 3.1. Переключатель режимов
- Компактный сегмент-переключатель (2 варианта: «Сводка» | «Модули»), место — под шапкой `_ScreenHeader` или справа в ней (открытый вопрос №8).
- Состояние: `enum OpsHomeMode { brief, carousel }`, хранится в `SharedPreferences` (ключ `ops_home_mode`), как уже сделано для порядка карусели.
- Переход между режимами — `AnimatedSwitcher` (fade + лёгкий вертикальный slide, `SieMotion.base`). Обе ветки уже строятся в `build`, меняется только видимая.

### 3.2. Приветствие (шапка Сводки)
- Текст по локальному времени (`DateTime.now().hour`): утро / день / вечер / ночь (границы — открытый вопрос №3).
- Формат: «{Приветствие}, {ОПЕРАТИВНИК}» + опц. одна строка статуса (уровень/XP или сводный счётчик задач/привычек на сегодня).
- Имя берётся из `userProfileProvider` (как в `_ScreenHeader`).

### 3.3. Блоки модулей — спецификация

Общая анатомия блока (карточка `SieGlassCard`/`flatCard`):
- **Превью-графика** модуля (переиспічем существующие `_BreathSpherePreview` / `_HabitMatrixPreview` / `_FocusRingPreview` / `_PlanningPreview` / `_DefragPreview`) — как акцентный визуальный элемент (напр. слева-аватар или фон-справа; открытый вопрос №5).
- **Обращение системы** (заголовок-текст) + **персональная выжимка**.
- **CTA** (весь блок кликабелен → `_onBranchTap`-эквивалент в соответствующий экран).

**Планирование (`planning`)** — данные из `planningProvider`:
- Выбрать активную цель (приоритет/ближайший дедлайн — открытый вопрос №4) и одну задачу «на сегодня».
- Текст: цель + одна задача + «А также ещё {N} задач…» (если >1).
- Пусто (нет целей): призыв «Развернуть первую операцию».

**Привычки (`habit_archive`)** — данные из `habitsProvider` (`isScheduledOn`, `isAvoid`, `streaks`, `logDates`):
- Есть невыполненные сегодня: «Осталось {N} протоколов на сегодня» + первая/список.
- Всё выполнено: поздравление + блок avoid-привычек («Избавиться») с мотивацией (напр. «День {streak} без срыва — так держать»).
- Нет привычек: призыв создать.

**Фокус / Дыхание / Медитация** — данные из `focusTimerProvider` и БД (`localFocusSessions`, `breathingSessionsForWidget()`, `meditationSessionsForWidget()`):
- Призыв выполнить практику + «Последняя сессия: {дата/длительность}» или «Сессий ещё не было».

### 3.4. Покрытие текущего функционала (чтобы отказаться от карусели)
- **XP / уровень / бейдж** — в шапке Сводки (переиспользовать логику `_ScreenHeader`).
- **Советы дня** (`_DailyTipBanner`, `tips_provider`) — отдельный блок сводки или в приветствии (открытый вопрос №2).
- **Суточный Авангард → лидерборд** (`_LeaderboardTile`) — блок сводки с CTA в `LeaderboardScreen`.
- **Заметки к целям** (dismissible-баннер) — в блок Планирования либо опустить (открытый вопрос №2).
- **Общие для экрана**: welcome-модал + автозапуск тура, `_FloatingNavBar`, pull-to-refresh, offline-режим, действия шапки (уведомления/поиск/выход) — остаются на уровне экрана, одинаково для обоих режимов.

### 3.5. Данные / провайдер
- Ввести `operationalBriefProvider` (или набор `select`-ов поверх существующих провайдеров), агрегирующий per-module выжимку. Значительная часть логики уже реализована в home-widget-провайдерах (`planning_widget_provider`, `habits_widget_provider`, `focus/breathing_widget_provider`) — **переиспользовать/вынести общее**, не дублировать.
- Всё offline-first (Drift), сеть не обязательна для базовой сводки (кроме tip/leaderboard).

### 3.6. Состояния
- Загрузка: скелетоны блоков (`SieSkeleton`).
- Ошибка/офлайн: блоки деградируют до простого CTA (как карусель работает офлайн).
- Пустые данные: призывные тексты вместо статистики.

## 6. Открытые вопросы

1. **Набор и порядок блоков** в Сводке: фиксированный (Планирование → Привычки → Фокус → Дыхание → Медитация) или учитывать пользовательский порядок карусели (`_orderedSlugs`)? Нужны ли reorder/скрытие блоков в Сводке?
2. **Советы дня, Суточный Авангард, «Заметки к целям»**: делать отдельными блоками сводки, свернуть в приветствие/шапку, или опустить часть?
3. **Приветствие**: границы времени суток и формулировки (утро 5–11 / день 11–17 / вечер 17–23 / ночь 23–5?). «Оперативник» как обращение — везде?
4. **Выбор «активной цели» и «задачи на сегодня»** в блоке Планирования: по приоритету, ближайшему дедлайну или первой незакрытой? Что считать «задачей на сегодня» — с дедлайном = сегодня, просроченные, или просто следующая незакрытая?
5. **Как обыграть превью-графику** в блоке: слева как «аватар системы», справа мини-превью, или фоном блока под текстом? Анимации превью оставить живыми или статичный кадр в ленте (перф)?
6. **Режим по умолчанию**: для новых пользователей — Сводка (рекомендую) или карусель? Для существующих — сохранить карусель до явного переключения?
7. **Тон обращений**: строго «системный/военный» стиль (как весь UI: «оперативник», «протоколы», «операции») — подтвердить формулировки, чтобы затем зашить в i18n.
8. **Переключатель**: стиль (сегмент-таб «Сводка/Модули» / две иконки) и место (в шапке справа / отдельной строкой под шапкой). Иконки?
9. **Медитация**: у неё нет отдельного «превью-виджета кольца» как у фокуса — используется `_DefragPreview`. Подтвердить, что он подходит как визуал блока.

## 7. Этапы реализации (после согласования)
1. Инфраструктура: `enum OpsHomeMode` + persist + переключатель + `AnimatedSwitcher` (Сводка пока = заглушка). Карусель не трогаем.
2. Шапка Сводки: приветствие по времени + XP/уровень.
3. Блоки Планирования и Привычек (самые data-rich).
4. Блоки Фокус / Дыхание / Медитация (+ последние сессии).
5. Покрытие остального (советы дня, лидерборд) блоками.
6. Полировка: скелетоны, offline-деградация, анимации, i18n ru/en.
7. Проверка на разных масштабах экрана (`.s`/textScaler уже в силе), APK на устройство.
